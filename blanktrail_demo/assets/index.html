BlankTrail Proxy — challenge pass-through demo

Two lanes, one target list. The baseline lane is a bare Python client; the other goes through a BlankTrail port. Everything here is client-side.

Targets

Test only what you are allowed to test.

Baseline lane

Give the baseline lane the same upstream the BlankTrail port uses. Then both lanes leave from one IP and the difference between them is the fingerprint and the solver — nothing else.

BlankTrail lane

Ports you already opened in BlankTrail. One line is a fixed port; several lines are a pool, used round-robin across the targets.

The key is sent to your own BlankTrail instance and is never stored.

Transport and TLS

How many targets run at once. 1 keeps every target strictly one at a time, the original behaviour. Pause min/max above are applied per worker, not shared across the run — with several workers going, the effective request rate against the target multiplies accordingly.

Verification runs on the BlankTrail lane and is part of the measurement: it proves the substituted certificate is well-formed and its SAN matches the host. requests and httpx ignore the OS store on their own, so the demo builds the trust context itself.
